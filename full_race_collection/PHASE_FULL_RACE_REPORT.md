# APEX-R full-race collection report

Generated by `collection_pipeline.py`. This report covers collection steps 1–5:
read the prior handoffs, apply the protected-session guard, validate three
races, expand only after that gate passes, and export/checksum/package the
result. No model training, label creation, holdout scoring, decision-engine
change, or replay was performed.

## Result

The collection completed using the already pinned Phase 2/Phase 3 caches. It
issued **0 new network requests** and verified the SHA-256 of each cached source
payload before parsing it. The protected-session exclusion manifest was read
before source access; no protected session was requested or included.

The three-race gate passed:

| Race | Split | Expected drivers | Valid laptime files | Lap rows | Result |
| --- | --- | ---: | ---: | ---: | --- |
| 2018 Chinese Grand Prix | train | 20 | 20 | 1,115 | PASS |
| 2019 Australian Grand Prix | train | 20 | 20 | 1,041 | PASS |
| 2020 Austrian Grand Prix | train | 20 | 20 | 1,140 | PASS |

Only after all three passed did the pipeline expand to the approved manifest.

Split coverage is 41 complete train races / 44,688 lap rows, 14 complete
validation races / 14,680 lap rows, and 14 complete development-test races /
14,716 lap rows. The development-test material is collected as context only;
no model result was computed from it.

The single quarantined race is **2018 Italian Grand Prix**. Its source driver
universe has 20 entries, but `HAR/laptimes.json` is empty and `ALO`/`RIC` have
lap gaps. It remains in `race_context.csv` as `FAIL` with the exact reason and
is not included in `driver_laps.csv.gz` or event candidates.

“Complete” is intentionally narrow: every driver listed in that race’s
`drivers.json` has a readable laptime payload starting at lap 1 with
contiguous observed lap identifiers. This is complete source lap context, not
proof of continuous sub-lap telemetry or complete physical track coverage.

## Events and candidates

The exported public-event table contains **8,020 source-recorded public event
rows** from the 69 complete races: **2,274 public pit-stop records** and
**5,746 race-control messages**. These are verified as source-recorded public
events only; no row is called an overtake.

The pipeline found **2,095 unresolved position-swap candidates across 68
races**. A candidate requires the same driver pair to be ordered immediately
behind/ahead at one lap boundary and reversed at the next observed boundary.
It is marked `UNRESOLVED_CANDIDATE` because the source does not supply a
verified sub-lap pass timestamp. Candidates with pit context on either boundary
or an associated race-control lap retain those flags rather than being silently
discarded. There are **0 verified overtake events** in this collection.

Candidates are evidence for later review, not labels. A later phase must still
exclude or resolve pit-related order changes, retirements, lapping/unlapping,
timing corrections, and pass/repass sequences using a source with adequate
temporal resolution.

## Provenance and preservation

The source manifest records 1,654 source references for the included races:
1,379 TracingInsights laptime payloads, 69 driver manifests, 69 weather
payloads, 69 race-control payloads, and 68 public pit-stop source references.
Each has URL, cache path, byte count, expected/actual SHA-256, retrieval/status
metadata, and a `SOURCE_PAYLOAD_NOT_REPACKAGED` disposition. Raw source payloads
were not copied into this package because redistribution terms for the data
payloads remain unresolved; retrieval/hash metadata is provided instead.

The before/after hashes of all consumed Phase 2/3 input artifacts match. The
base telemetry and previous phase outputs were not modified.

## Limitations and next gate

This collection repairs the “selected-lap-only” context limitation for the
available TracingInsights lap-level records, but it does not create a
second-level overtake ground truth. There is no verified absolute OpenF1
session-key mapping for these 2018–2022 manifest races in the approved cached
inputs, so no OpenF1 outcome request was made. Historical pit time-of-day values
also remain source context, not proof of live publication latency.

The correct next gate is a separate evidence review and outcome-resolution
phase. Do not train on `unresolved_position_swap_candidates` as verified
overtakes. The exported context is suitable for bounded historical/proxy
investigation, subject to that review; it is not by itself deployable-model
training data.

artifact row counts, duplicate driver/lap keys, source immutability, protected
